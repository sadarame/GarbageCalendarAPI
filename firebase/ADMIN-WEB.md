# 地域情報登録画面

公開先: https://garbagecalendar-region-admin.web.app

Firebase の v2SharedSchedules に管理者登録します。自治体・地区名でIDを決定し、revisionによる更新競合を検出します。既存のアプリ投稿と移行済みデータは変更しません。公開した地域は既存アプリの近隣検索対象になります。

## 表示アイコン

各収集ルールの「表示アイコン」で、種類名とは別にイラストを指定できます。選択したイラストは入力欄の下にプレビューされます。「種類名から自動」は従来の名前による選択です。指定は iconType として保存し、対応版アプリのカレンダーとウィジェットで使用します。アプリ内にアイコン選択欄は設けません。

## アクセス

Basic認証はありません。URLを開くとすぐに利用でき、アクセスした人は地域情報の一覧取得・登録・更新ができます。

`regionalAdminWeb` がHTML・JS・CSS・管理APIを配信します。応答は `private, no-store` です。APIは同一サイトのOrigin・JSON・専用ヘッダーを検証し、入力検証・revision競合検出を通します。これらは利用者の認証ではありません。旧Firebase管理APIは引き続き管理者権限を要求します。

## dot に渡す作業指示の例

自治体の公式サイトから収集情報を調べ、この登録画面に入力してください。対象地区・町丁目を混同せず、出典URLと確認日を記録してください。曜日が複数ある場合はルールを分けてください。年末年始の休止日・振替日は例外日に設定してください。曖昧な情報は公開せず、下書きに保存して確認メモへ残してください。

既存の登録地域は一覧から選ぶと修正できます。住所の識別項目は変更できません。別地区は「新しい地域」から作成してください。公開中の情報を下書きに戻すと近隣検索から非表示になります。端末保存はそのブラウザ内のみで、サーバーへは登録されません。

## 配備

firebase.json の hosting.site は garbagecalendar-region-admin を指定します。

`npx --yes firebase-tools@15.34.0 deploy --only functions:garbage-v2:regionalAdminWeb,hosting --project garbagecalendar-1923d`

functionsのビルド時にadmin-webの3ファイルとiconsフォルダーをlib/admin-web-assetsへコピーします。Hostingの公開ディレクトリは空のhosting-publicとし、全リクエストをregionalAdminWebへ転送します。管理APIと同一オリジンで配信する構成です。

Node.js 22で実行してください。古い単体配布版Firebase CLIではSDKのESM読み込みに失敗するため、上記のnpm版CLIを使います。

テストは functions ディレクトリで `npm test`。管理画面・管理機能のみの検証は `npm run build && node --test test/admin-web.test.js test/admin.test.js`。

## JSON一括登録・更新（Phase 1）

管理画面の「JSON一括登録・更新」でファイルまたは貼付から読み込み、「保存せず検証・差分表示」→地区を選択→一括保存→結果／DB読戻しJSONのダウンロードを行います。画面の一覧には読戻し結果を反映するため、地区ごとの一覧再取得はありません。失敗・競合した地区だけ再検証できます。検証済みの地区を選択して「選択した地区を確認して一括公開」を押すと、公開予定の全項目・ルール・出典を確認できます。確認後に選択地区のみ保存・公開します。検証後の競合や公式日付の不一致は地区単位で拒否し、結果を表示します。処理後の再操作には再検証が必要です。

入力は地区オブジェクトの配列、または `{"districts": [...]}`。仕様書・PDF・`examples` を含む提案書は取込対象ではありません。最大100地区、ファイル2MB、日付比較期間は最大10年です。初期表示では地区を取得しません。都道府県と市区町村を指定したときだけ50件を取得し、続きは明示的に読み込みます。検索は表示中の地区だけが対象です。全地区バックアップは確認後の手動操作のみで、一覧を1巡して保存し、個別読戻しや2回照合は行いません。バックアップはトランザクションスナップショットではなく、取得中の更新は混在する場合があります。保存・公開後は該当行だけを更新し、検索語・選択地区・一覧とページのスクロール位置を保持します。

```json
[
  {"districtId": "既存DBのID", "notes": "確認メモだけを更新"},
  {
    "prefecture": "埼玉県", "municipality": "検証町", "district": "全域",
    "name": "検証町 全域", "latitude": "36.07", "longitude": "139.36",
    "sourceUrl": "https://example.jp/calendar", "checkedOn": "2026-01-01",
    "validFrom": "2026-04-01", "validTo": "2027-03-31",
    "rules": [{"garbageType": "廃乾電池", "iconType": "危険・有害",
      "schedule": "指定日のみ", "specificDates": ["2026-05-16", "2026-11-07"]}]
  }
]
```

上記は操作例で、実際の地区登録用データではありません。

- `districtId` は既存FirestoreドキュメントIDです。ID指定時はその地区を更新し、改名してもIDは変わりません。IDなしは都道府県・自治体・地区の完全一致で照合し、複数一致・同一ファイル内重複はエラーです。未一致時のみ現行の決定的ID方式で新規作成します。管理者登録以外のデータは更新しません。
- 省略項目と既存公開状態を保持します。`status` は公開命令として扱わず、通常の一括保存では新規は下書きです。確認画面で明示した一括公開のみ、APIの `publish: true` で公開状態にします。`rules` を指定した場合は配列全体の置換です。指定しなければ既存ルールを保持します。
- `excludedDates` / `additionalDates` は日付配列またはカンマ区切り文字列を受け付け、DBは従来どおり配列です。追加・除外の重複、実在しない日付、期間外の例外日、未対応項目・周期・アイコンは拒否します。緯度経度は既存どおり小数2桁です。
- 有効期間は両端を含み、省略時は従来どおり制限なしです。地区期間とルール期間の積集合で計算します。`指定日のみ` は指定日集合だけを生成し、翌年へ複製しません。通常ルールの追加・除外日とも併用しません。
- 任意の `expectedDatesByGarbageType` は品目名→日付配列の辞書です。有効期間の両端が必要で、同じ品目の複数ルールを合算し、`missingDates` / `extraDates` を表示します。不一致は保存を拒否します。検証結果は公式情報の正しさや公開承認を意味しません。
- `uiListText` / `checkedAtISO` / `publicationEligible` / `registrationEligible` は保存せず、その扱いをプレビューに表示します。エクスポートのrevision・更新者等は読戻し用であり、入力で書き換えられません。
- 検証時の地区データ全体の指紋をトランザクション内で再確認します。差分確認後に別編集があれば `conflict` として保存しません。各地区を原子的に保存し、`created` / `updated` / `unchanged` / `error` / `conflict` を返します。未変更時はrevisionも増やしません。
- 保存結果にはDBから読み直した `districts` と `readbackMatches` を含みます。通信切断で結果不明の場合も同じ入力を再検証し、成功済みを確認できます。

APIは `previewAdminBulkV2` / `saveAdminBulkV2` / `exportAdminBulkV2`。Callable版は従来と同じ `scheduleAdmin` 権限を必須とします。Web版は既存の同一Origin・JSON・専用ヘッダー検査を維持します（上記「アクセス」のとおり、現行Web版に利用者認証はありません）。

アプリ・ウィジェット・通知用のモデルと予定計算にも期間・指定日を追加しています。旧アプリは新項目を解釈できないため、本番反映時には対応アプリの配布と地区データの再取得を合わせて確認してください。2026-10-20に管理画面・関連APIをデプロイ済みです。本番データの登録・移行およびApp Storeへのアプリ配布は実施していません。

### 検証

- `functions` で `npm test`：既存テスト＋一括取込の回帰テスト。
- 専用ローカルFirestoreエミュレーター（`demo-bulk-import`, `127.0.0.1:8188`）で `FIRESTORE_EMULATOR_HOST=127.0.0.1:8188 node --test test/bulk.emulator.js`：同時新規登録、競合、改名、公開状態、読戻し、再取込。新しいエミュレーター／空のテストDBで実行します。
- `python3 GarbageCalendar/scripts/check_calendar_regressions.py`：Swiftの実モデル・予定計算による年末年始、期間境界、指定日、既存周期の確認（ワークスペースのルートで実行）。

## 登録住所マップ

`/map` は登録済みの管理地区を一覧・日本地図で表示します。初期表示では地区APIを呼びません。都道府県を選ぶと、その都道府県の市区町村名だけ取得します。市区町村を選び「この地域を表示」を押すと、その市区町村だけを200件単位で取得します。取得後は地区名・公開状態・表示範囲で絞り込めます。件数付きピンは近接地点をまとめたもので、拡大すると分かれます。同一座標の地区はポップアップ内にまとめて表示します。座標のない地区は一覧のみ表示します。API・既存データへの書き込みは行いません。

背景地図はOpenStreetMap、描画は同梱のLeaflet 1.9.4を使用します。地図ページだけCSPでタイル画像とLeafletのインラインスタイルを許可し、編集画面のCSPは維持します。地図・スタイル・vendorファイルもビルド時にコピーします。

2026-10-25: 登録住所マップをFirebase Hostingへ公開。単体テスト46件に合格し、実データ2,205地区の全件取得、草加市41件の検索、下書き250件の絞り込み、地点詳細、モバイル幅を確認。公開URL: https://garbagecalendar-region-admin.web.app/map

2026-10-25 追加改善: 地図専用の `listMapMunicipalities` / `listMapSchedules` を追加。地区取得は都道府県・市区町村を両方必須とし、収集ルール・管理メモ等を送信しない投影クエリを使います。候補は都道府県ごとにブラウザ内でキャッシュ。地域変更時は通信中断と世代番号で古い結果を破棄します。従来の登録編集画面の一覧APIは変更しません。回帰テスト51件に合格。

本番反映後、埼玉県の市区町村候補57件・737バイト、草加市の地区41件・11,077バイトを確認。草加市APIの実測は約0.43秒（単発の観測値、通信環境等に依存）。

2026-10-25: 背景地図サービスを廃止し、日本の都道府県を描くインラインSVG（約45KB）に変更。地球地図日本由来のdataofjapan/landのGeoJSONを簡略化して作成し、画面内に出典を掲載。都道府県のクリック・キーボード選択、選択県の拡大、日本全体への復帰に対応。Leafletや外部地図タイルへの通信は行いません。地区は一覧と詳細で表示します。

## 2026-11-02 ローカル修正（未デプロイ）

- 通常登録から全国一覧の自動取得を除去。保存・公開後は応答中の対象地区だけを画面に反映。
- 一括検証・保存は各段階最大4地区を並列処理。最大100地区、入力順の結果、地区ごとのエラー、競合検知を維持。
- ID指定・住所変更なしの一括更新は地区名検索を省略。対象1地区につき検証1読取り＋トランザクション1読取り＋対象だけの保存確認1読取り（再試行がない場合）。
- 単体更新は省略項目を既存データから保持し、画面は変更項目だけ送る。読み込み済みフォームのrevision競合検知は維持。住所指定の上書きは既存の完全一致IDを優先し、未登録なら安定IDで作成する。
- rulesを明示すれば配列全体を置換する。省略すれば保持。明示的な公開・下書き操作は維持。
- 本番DBへアクセスしないモックで検証。元リポジトリは未変更。適用時は保全時のハッシュと比較し、その後の変更があれば統合してから反映する。
